How I vibe code

Vibe coding is not typing a wish and hoping. It is a loop, and the loop is the skill.

Describe the outcome

I start by describing what the software must do, in plain words, including the edge cases. A clear prompt is a clear spec, and a vague prompt is how you get vague software.

Iterate on the prompts

The first result is a draft. I refine the prompt, correct the mistakes, and push the AI toward the exact behaviour I want, feature by feature, until it matches the spec.

Test what comes back

I run the code, break it on purpose, and check the output myself. If it does not work, I fix the prompt or fix the code by hand. Nothing ships untested.

Ship and refine

When it works, it ships. Then I keep improving it from real use, the same way I improve support processes from real tickets.

Questions people ask me

What is vibe coding?

Vibe coding means building software by describing what you want to an AI in plain words, then iterating on the prompts until the software works. You still need to know what good software looks like, how to test it, and when the AI is wrong. The AI writes the code, and you direct it.

Does vibe coding count as prompt engineering?

Yes. Prompting an AI, iterating on the prompts, and getting working software out of it is prompt engineering in practice. My MT5 Trade Manager is the sample. I am honest that this is a stretch for dedicated prompt engineer roles, and the shipped products are the proof I offer.

Can you build custom tools for a team?
